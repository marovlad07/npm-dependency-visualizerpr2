# Граф зависимостей npm

Практическая работа №2 по конфигурационному управлению.
Группа ИКБО-71-25, вариант 14. Язык реализации: Python 3.10+.

## Этап 1

Минимальное CLI-приложение принимает имя пакета, версию, URL реестра
либо путь к тестовому репозиторию и флаг тестового режима.
Опция `--mode config` выводит параметры в формате ключ-значение.
Ошибочные параметры завершают программу с кодом 2.

```powershell
.\run.bat --package is-odd --version 3.0.1 --mode config
.\test.bat
```

Внешние Python-библиотеки и сборка не нужны. Исходники находятся в `src`,
тесты в `tests`. На другом компьютере установите Python 3.10+.

## Этап 2

Получение метаданных выполняется прямым HTTP-запросом через `urllib`.
Версия корневого пакета задается полностью: например `3.0.1`.
Данные берутся из `versions[version].dependencies`, а не из `latest`.
Встроенный SemVer-резолвер поддерживает точные версии, теги, `^`, `~`,
сравнения, частичные версии, `x`, `*`, дефисные диапазоны и `||`.

```powershell
.\run.bat --package is-odd --version 3.0.1 --mode direct
```

## Этап 3

Граф строится BFS с очередью `deque`, без рекурсии. Узел идентифицируется
парой `(имя, версия)`. Множество обнаруженных узлов предотвращает
бесконечный обход циклов; все ребра, включая обратные, сохраняются.
Для каждого диапазона выбирается максимальная подходящая версия.
Сетевые ответы кешируются в памяти. Лимит 5000 узлов вызывает ошибку,
а не выдает незаметно обрезанный граф.

```powershell
.\run.bat --test --repository examples/cycle.json --package A --version 1.0.0
.\run.bat --test --repository examples/diamond.json --package A --version 1.0.0
.\run.bat --package is-odd --version 3.0.1 --mode graph
```

Вывод `graph` имеет формат JSON. Примеры `chain`, `diamond`, `cycle`,
`empty`, `self`, `versions` показывают цепочку, общую зависимость,
цикл, отсутствие зависимостей, петлю и разные версии одного пакета.
Недостижимый Z из `diamond.json` не входит в граф корневого A.

## Этап 4

Обратные зависимости вычисляются тем же BFS на графе с перевернутыми
ребрами. Показываются прямые и все транзитивные зависимые пакеты.
Сам целевой пакет исключается из результата даже при цикле или петле.
В тестовом режиме анализируется весь файл репозитория, включая пакеты,
недостижимые из указанного корня. Для реального npm анализ ограничен
графом выбранного корня: npm API не дает полный список глобальных
обратных зависимостей. Поэтому корнем следует выбирать верхний пакет,
а `--target` указывает интересующий узел внутри его графа.

```powershell
.\run.bat --test --repository examples/diamond.json --package D --version 1.0.0 --mode reverse
.\run.bat --test --repository examples/cycle.json --package A --version 1.0.0 --mode reverse
.\run.bat --test --repository examples/empty.json --package A --version 1.0.0 --mode reverse
.\run.bat --package is-odd --version 3.0.1 --mode reverse --target is-number@6.0.0
```
