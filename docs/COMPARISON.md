Источник: https://registry.npmjs.org.

| Пакет | Узлы программы | Связи программы | Узлы npm | Связи npm | Итог |
|---|---:|---:|---:|---:|---|

| is-even@1.0.0 | 5 | 4 | 5 | 4 | Полное совпадение |

Совпадают не только количества, но и множества узлов `имя@версия`
и направленных связей `(родитель, зависимость)`.
Числа получены фактическим запуском программы и npm, а не оценкой.
Машиночитаемый итог: [results/comparison.json](results/comparison.json).

## Методика

1. Наша программа читает метаданные прямыми HTTP-запросами и строит граф BFS.
2. В отдельной временной папке создается `package.json` с одной зависимостью,
   у которой зафиксирована точная версия.
3. Только для независимой проверки запускается штатный npm:

```text
npm install --ignore-scripts --omit=dev --omit=optional --legacy-peer-deps
            --no-audit --no-fund --package-lock=false
npm ls --all --unicode=false
npm ls --all --json
```

Команда install выше перенесена на две строки для чтения; при ручном запуске
передайте все аргументы одной командой. Скрипты скачанных пакетов отключены.
Каждый пример устанавливается в собственную чистую папку.
Проверочные инструменты не входят в исходники приложения.

4. Из JSON-дерева npm берется поддерево анализируемого пакета; служебный
   проект-обертка исключается. Повторные появления одинаковых узлов
   объединяются по имени и версии. Сравниваются множества узлов и ребер.

## Сохраненные результаты

- `results/*-graph.json` — граф нашей программы.
- `results/*-npm-ls.json` — фактический JSON-вывод npm.
- `results/*-npm-tree.txt` — штатная текстовая визуализация npm.
- `graphs/*.dot` — описание тех же графов на языке Graphviz.
- `gallery.html` — галерея трех изображений после запуска `demo_all.bat`.

Для всех трех примеров содержательных расхождений нет.
Разница в представлении ожидаема: npm выводит дерево, Graphviz рисует граф.

## Почему на других пакетах результаты могут отличаться

Программа рассматривает только поле `dependencies`. Поля
`devDependencies`, `peerDependencies`, `optionalDependencies` отдельно
не обходятся. Для каждой связи независимо выбирается наибольшая версия,
удовлетворяющая диапазону; lock-файл, дедупликация установки, платформа,
поле `engines` и автоматическая установка peer-зависимостей не учитываются.
Один пакет с разными версиями представлен разными узлами.

Git-, file-, workspace- и tarball-зависимости не входят в поддерживаемый
формат реестра и вызывают явную ошибку. Метаданные реального реестра
могут меняться; диапазоны могут разрешиться иначе при повторной проверке.
